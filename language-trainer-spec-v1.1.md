# Языковой тренажёр «Карточки» — спецификация v1.1

Дата: 2026-11-20. Статус: дизайн согласован с заказчиком, код не начат.

---

## 1. Что это

Статический сайт (GitHub Pages, без бэкенда) для заучивания слов и фраз: флеш-карты и задания на перевод с вводом ответа. Базы пользователи делают сами в txt/md и подключают тремя способами (§3). Автор сайта размещает на нём ссылки на свои рекомендованные материалы; свои базы любой пользователь загружает со своего устройства.

Принципы:

- Без сервера: всё работает в браузере, данные хранятся в localStorage.
- Без сборки: vanilla HTML/CSS/JS, два html-файла.
- База — обычный текстовый файл, который правится в любом редакторе.
- Телефон — основной сценарий: крупные кнопки, тап по всей карточке.

## 2. Сущности

- **Колода** — один файл `.md` или `.txt`, содержит флеш-карты и/или задания.
- **Флеш-карта** — сторона A (слово / фраза / предложение / картинка / аудио) и сторона B (перевод или расшифровка на родном языке).
- **Задание** — `prompt` (что показываем) и `answer` (что нужно написать). Проверка — самооценкой: сайт показывает правильный ответ с подсветкой отличий, пользователь отмечает «Знал / Не знал».
- **Сессия** — прогон набора карточек с выбранным режимом и направлением.
- **Прогресс** — счётчики «знал / не знал» по каждой карточке, хранятся в браузере.

## 3. Источники колод (три способа)

1. **Рекомендованные** — список ссылок, захардкоженный в репозитории сайта (`decks.json`). Видны сразу при первом открытии; это материалы автора сайта.
2. **Ссылка** — raw-URL на GitHub (`raw.githubusercontent.com`, CORS открыт). Сайт скачивает текст, кэширует его в localStorage, после чего колода доступна оффлайн. Кнопка «Обновить» перечитывает файл из сети. Поддерживается зеркало jsDelivr (`cdn.jsdelivr.net/gh/...`).
3. **Локальный файл** — выбор файлов с ПК/телефона (мультивыбор: md/txt + лежащие рядом картинки и аудио). Содержимое сохраняется в localStorage, поэтому колода остаётся на сайте после перезагрузки страницы; кнопка «Загрузить заново» подхватывает правки файла с диска. Ограничение: весь localStorage ≈ 5 МБ — тексты колод помещаются свободно, тяжёлые base64-картинки в постоянный кэш не пишутся (живут только в текущей сессии).

Подключать можно сколько угодно колод; одна сессия может гонять несколько колод одновременно.

## 4. Формат базы v1.1

### 4.1 Общие правила

- Один файл = одна колода. Расширения: `.md` (полный синтаксис) и `.txt` (табличный, §4.7).
- Кодировка UTF-8.
- Шапка с метаданными — YAML frontmatter в начале файла, необязательна.
- Записи делятся на однострочные и блочные; строки `---` и пустые строки — визуальные разделители (можно не ставить). Заголовки-переключатели: `# Карточки` — далее идут флеш-карты, `# Задания` — далее задания на ввод; обычные заголовки разбор не меняют. Если заголовков нет вообще, работает старый синтаксис: строка из двух полей — флеш-карта, из трёх и более — задание.
- Однострочная запись: поля через « | » — сторона 1, сторона 2, затем необязательные подсказка и теги. «;» внутри первых двух полей разделяет варианты, первое значение — каноничное (§4.8). Запись начинается с края строки; строка с отступом внутри блочной записи — продолжение значения.
- Блочная запись начинается строкой с ключом поля и продолжается до пустой строки, `---`, заголовка или следующей однострочной записи; порядок записей в файле сохраняется.
- Ключи полей — только английские (финальное решение): `front`, `back`, `prompt`, `answer`, `alt`, `alt1`, `alt2`, `hint`, `audio`, `tags`, `id`, `direction`, `reverse`.
- Неизвестные ключи не ломают парсер: они сохраняются как метаданные и игнорируются (совместимость на будущее).

### 4.2 Шапка колоды

```markdown
---
title: Английский A1 — Урок 1. Приветствия
lang: en        # изучаемый язык
base: ru        # язык переводов
reverse: true   # флеш-карты показывать в обе стороны
description: Первая колода: приветствия и знакомство
---
```

### 4.3 Флеш-карты

Строчная форма (основная для слов):

```markdown
hello | привет
good morning | доброе утро; добрый день
See you tomorrow! | До завтра! | говорится при прощании | приветствия
![](img/dog.jpg) **dog** | собака
```

Поля через ` | `: сторона A, сторона B, затем необязательные подсказка и теги. `;` в первых двух полях разделяет варианты — первое значение каноничное (§4.8). Литеральная вертикальная черта экранируется: `\|`.

Блочная форма (длинные фразы, картинки, аудио и точный контроль):

```markdown
front: |
  Good morning, how are you?
back: |
  Добрый день, как дела?
hint: формальное приветствие
audio: audio/good-morning.mp3
tags: приветствия, формальное
```

Поля флеш-карты: `front`, `back`, `alt1`, `alt2` (варианты сторон; старое `alt` работает как `alt2`), `hint`, `audio` (можно несколько — плейлист), `tags` (через запятую), `id` (стабильный идентификатор), `reverse` (true/false — переопределяет шапку колоды).

### 4.4 Задания

Однострочная форма (в секции `# Задания`; 2 поля — минимум, 3-е — подсказка, 4-е — теги):

```markdown
Привет, как дела?; Здравствуйте, как ты? | Hello! How are you?; Hi! How are you? | неформальное приветствие | приветствия
```

Блочная форма (длинные фразы, картинки, аудио):

```markdown
prompt: |
  Привет, как дела?
answer: |
  Hello! How are you?
alt1: Здравствуйте, как ты?; Как ты поживаешь?
alt2: Hi! How are you?; How are you doing?
hint: неформальное приветствие
audio: audio/hello-how-are-you.mp3
tags: приветствия
```

- `prompt` — что показываем (текст / картинка / аудио); `answer` — эталон.
- `alt1` — допустимые варианты стороны 1 (принимаются, когда вводится сторона 1 — после ⇄ или в направлении l2l1); `alt2` — варианты стороны 2. Старое поле `alt` работает как `alt2` (совместимость). Для подсветки diff берётся каноничное значение стороны, совпадения с вариантами отмечаются бейджем «Совпадает с эталоном» (§5.3).
- В блочных `prompt`/`answer` символ `;` — часть текста и не разделяется; варианты перечисляйте в `alt1`/`alt2`. В однострочных записях, наоборот, `;` — разделитель вариантов, и текст с `;` нужно писать блочной формой.
- `direction: l2l1 | l1l2 | both` — необязательная фиксация направления задания. По умолчанию `both`: задание можно переворачивать прямо на сайте (§5.3).

### 4.5 Картинки

Допустимы в любом поле, все три способа:

- `![](img/dog.jpg)` — путь относительно файла колоды; при загрузке по ссылке резолвится от raw-URL;
- `![](https://...)` — внешний хостинг;
- `![](data:image/png;base64,...)` — картинка, вшитая в файл.

При локальной загрузке — мультивыбор файлов: сайт связывает относительные пути в памяти через blob-URL.

### 4.6 Аудио

- Поле `audio:` (можно повторять несколько раз — плейлист с кнопками «дальше/назад»).
- Пути как у картинок: относительный `audio/good-morning.mp3`, внешний URL.
- Форматы: mp3, ogg, m4a, wav.
- Воспроизведение — кнопка на карточке; автоплей при перевороте — настройка, по умолчанию выключена.

### 4.7 txt/TSV (массовый ввод)

- Строка, начинающаяся с `#` — комментарий, игнорируется.
- Колонки через Tab: **2 колонки** → флеш-карта (`front<TAB>back`); **3 колонки** → задание (`prompt<TAB>answer<TAB>tags`).
- Варианты перечисляются через `;` прямо в колонке своей стороны (первое значение — каноничное); в задании третья колонка — теги. В .txt нет секций, подсказки и многострочных значений — для этого используйте .md.

### 4.8 Варианты и стороны записи

- У каждой записи две стороны: сторона 1 (`front`/`prompt`) и сторона 2 (`back`/`answer`); язык сторон не фиксируется — сторона 1 не обязана быть русской.
- Варианты стороны 1 задаются полем `alt1`, стороны 2 — полем `alt2`; старое `alt` работает как `alt2`. В однострочных записях варианты перечисляются через `;` прямо в поле стороны, первое значение — каноничное.
- Проверка ввода (§5.3) принимает канон или любой вариант той стороны, которую пользователь вводит; на флеш-картах варианты показываются строкой «Варианты: …» на своей стороне, в заданиях — «Тоже верно: …» после показа ответа.
- id считается по каноничным значениям сторон, поэтому добавление или правка вариантов не сбрасывает прогресс.

### 4.9 Идентификация карточек и стабильность прогресса

- id карточки = пользовательский `id:` или хэш (front + answer).
- Прогресс привязан к id: правки других карточек прогресс не трогают; правка текста самой карточки без явного `id:` сбрасывает её прогресс — в таком случае стоит указать `id:` явно.

## 5. Тренажёр

### 5.1 Старт сессии

- Выбор одной или нескольких колод, фильтр по тегам.
- Режим: **Карточки** / **Задания** / **Микс** (оба типа вперемешку). Режим фильтрует пул упражнений по типу: в «Заданиях» попадаются только задания с вводом ответа, в «Карточках» — только флеш-карты; «Микс» содержит оба типа.
- Направление: **Смешанно** (случайно на каждую карточку) / **Изучаемый → родной** / **Родной → изучаемый**.
- Режим «Повторить ошибки» — только карточки со счётчиком «не знал» > 0.
- Ограничение сессии по количеству карточек (по умолчанию — вся колода).

### 5.2 Флеш-карта

- Показ стороны A → **тап на телефоне / клик мышью / пробел** — переворот.
- Кнопка «Подсказка» — показывает текст поля `hint` (если задан).
- Кнопка аудио; автоплей при перевороте — по настройке.
- Самооценка, две кнопки: **«Знал»** (клавиша `1`) и **«Не знал»** (клавиша `2`).

### 5.3 Задание

- Показ prompt + поле ввода; `Enter` или кнопка — «Показать ответ».
- **Кнопка «Подсказка»**: каждое нажатие открывает одну ещё закрытую букву ответа в случайной позиции; закрытые буквы показываются как «•»; пробелы и знаки (`¿`, `¡`, `.`, `,`) видны сразу — они помогают держать структуру фразы. Число нажатий пишется в статистику.
- Показ ответа: эталон + пословная подсветка diff — совпавшие слова зелёным, отличающиеся красным. При сравнении регистр, знаки `¿?¡!.`,`,`, ё/е и ударения не учитываются. Варианты вводимой стороны перечисляются строкой «Тоже верно: …»; совпадение ввода с каноном или любым вариантом отмечается зелёным бейджем «Совпадает с эталоном» (§4.8).
- **Кнопка «⇄»** — переворот направления текущего задания на ходу: пользователь составил задание ru→en, захотел en→ru — переворачивает кнопкой, файл править не нужно.
- Самооценка: «Знал» / «Не знал».

### 5.4 Горячие клавиши (ПК)

| Клавиша | Действие |
| --- | --- |
| Пробел / Enter | Переворот карточки или «Показать ответ» |
| 1 | Знал |
| 2 | Не знал |
| H | Подсказка |
| F | Перевернуть направление задания |
| Esc | Выйти из сессии |

### 5.5 Прогресс

- localStorage по ключу «колода + id карточки»: счётчики знал/не знал, дата последнего показа, использованные подсказки. Дата в схеме — задел под будущий SRS без миграции данных.
- Экспорт и импорт прогресса JSON-файлом — перенос между ПК и телефоном.
- Статистика по колоде: всего / знаю / ошибки; сброс прогресса кнопкой.

## 6. Интерфейс

- Сборка: **один самодостаточный файл `index.html`** (CSS и JS внутри, без шага сборки). Тренажёр и инструкция — два экрана одного приложения с hash-навигацией (`#/`, `#/instruction`, `#/session`); демо-колода вшита в файл и работает без интернета.
- Инструкция — отдельный экран с сайдбар-навигацией по разделам, якорными ссылками и копируемыми примерами (§7).
- Язык интерфейса: русский по умолчанию + переключатель на English, выбор сохраняется.
- Шрифт интерфейса — моноширинный (стек `ui-monospace → Cascadia Mono → SF Mono → Menlo → Consolas → DejaVu Sans Mono → monospace`), все размеры текста заданы в rem от базы `html{font-size:16px}`.
- **Размер шрифта** — настройка на главной (блок «Настройки»): 85 / 100 / 115 / 130 / 150 %; выбор хранится в localStorage и применяется к базе rem при запуске, масштабируется весь интерфейс, включая кодбоксы инструкции.
- Мобильная вёрстка: крупные кнопки под большой палец, тап по всей карточке, всё помещается без горизонтального скролла.
- Горячие клавиши на ПК (§5.4).

## 7. Страница инструкции — содержание

1. **Быстрый старт за 5 минут** — готовый шаблон колоды целиком, кнопка «Скопировать».
2. **Формат базы** — шапка, секции `# Карточки` / `# Задания`, однострочные записи с вариантами через `;`, блочные записи, `alt1`/`alt2`, все поля, правила разделения и экранирования.
3. **Картинки** — три способа + как загружать локально с картинками.
4. **Аудио**:
   - поле `audio:` и где его писать;
   - **как создать свои аудио**:
     - **edge-tts** (рекомендуемый способ): бесплатно, нейроголоса Microsoft, десятки языков. Пример: `edge-tts --voice en-US-AriaNeural --text "Hello! How are you?" --write-media audio/hello-how-are-you.mp3`;
     - **gTTS** — простые Google-голоса, короткий Python-скрипт;
     - **Piper** — локальный оффлайн-синтез, быстрый, без интернета;
     - **Forvo** — живые записи носителей для отдельных слов;
     - платные сервисы максимального качества: Azure TTS, ElevenLabs, OpenAI TTS;
     - обычная запись голоса на телефоне;
   - заметка: позже в репозиторий добавим скрипт батч-генерации, который прочитает md-колоду и создаст mp3 для всех карточек сразу.
5. **Загрузка на сайт** — рекомендованные / ссылки (raw, кэш, «Обновить») / локальные файлы (мультивыбор, что сохраняется, лимит памяти).
6. **Прогресс** — как считается, экспорт/импорт, сброс.
7. **Горячие клавиши** — таблица.
8. **FAQ и шаблоны** — типовые вопросы и копируемые примеры колод.

## 8. Архитектура и репозиторий

```
repo/
  index.html          # весь сайт: тренажёр + инструкция (CSS/JS внутри)
  decks/
    en-a1-u1.md       # пример колоды
    fr-basics.txt     # пример TSV-колоды
    img/…             # картинки для колод
    audio/…           # аудио для колод
  README.md
```

- Рекомендованные колоды задаются массивом `RECOMMENDED_DECKS` в начале скрипта внутри index.html (автор сайта редактирует список ссылок).

- Хостинг: GitHub Pages. Сборка не нужна.
- Загрузка по ссылке: `fetch` на raw-URL (CORS открыт у `raw.githubusercontent.com` и `cdn.jsdelivr.net`).
- localStorage (~5 МБ): список подключённых источников, кэш текстов колод, прогресс, настройки. base64-картинки и blob-объекты в постоянный кэш не пишутся.
- Модули: `parser.js` (md/txt → колода), `storage.js` (кэш и прогресс), `session.js` (режимы, направление, подсказки), `ui.js` (рендер, hotkeys), `i18n.js` (RU/EN).

## 9. Сознательно отложено на потом

- SRS-интервалы (Leitner / SM-2) — схема данных уже готова.
- Cloze-пропуски: `Я иду в {{школу}}`.
- Импорт `.apkg` из Anki.
- Приватные репозитории (raw требует токен — без бэкенда не сделать).
- PWA / установка на телефон.
- Скрипт батч-генерации аудио для колоды.
- Манифест `decks.json` в репозитории колод пользователя (одна ссылка = все колоды).

## 10. Хронология решений

- **v1.0**: гибрид-синтаксис (строчно + блоком); один файл-урок с секциями; проверка самооценкой; оба направления; картинки всеми тремя способами; простой прогресс без SRS; raw-ссылки + кэш; интерфейс RU + EN.
- **v1.1**: ключи полей только английские; кнопка «Подсказка» в заданиях — открывает случайные буквы по одной; самооценка из двух кнопок; микс-режим с первого дня; локальные колоды сохраняются в localStorage; поле `audio:` и плеер; отдельная страница инструкции с навигацией; переворот направления задания на сайте кнопкой «⇄»; переворот карточки тапом/кликом/пробелом.
- **v1.2 (реализация)**: сборка сведена к одному самодостаточному index.html (тренажёр + инструкция + вшитая демо-колода); уточнено правило разбиения карточек — новая карточка также начинается после пустой строки перед `front:`/`prompt:`, короткие карточки идут по одной на строку; строки-шорткаты перед блочной карточкой тоже разбираются как карточки. Подтверждено тестами: 42 юнит-теста парсера и браузерный прогон (сессия, подсказка-буквы, diff, ⇄, EN, мобильная вёрстка 375px без переполнений).
