# Языковой тренажёр «Карточки» — спецификация v1.1

Дата: 2026-11-20. Статус: дизайн согласован с заказчиком, код не начат.

---

## 1. Что это

Статический сайт (GitHub Pages, без бэкенда) для заучивания слов и фраз: флеш-карты и задания на перевод с вводом ответа. Базы пользователи делают сами в txt/md и подключают тремя способами (§3). Автор сайта размещает на нём ссылки на свои рекомендованные материалы; свои базы любой пользователь загружает со своего устройства.

Принципы:

- Без сервера: всё работает в браузере, данные хранятся в localStorage.
- Без сборки: vanilla HTML/CSS/JS, два html-файла.
- База — обычный текстовый файл, который правится в любом редакторе.
- Телефон — основной сценарий: крупные кнопки, тап по всей карточке.

## 2. Сущности

- **Колода** — один файл `.md` или `.txt`, содержит флеш-карты и/или задания.
- **Флеш-карта** — сторона A (слово / фраза / предложение / картинка / аудио) и сторона B (перевод или расшифровка на родном языке).
- **Задание** — `prompt` (что показываем) и `answer` (что нужно написать). Проверка — самооценкой: сайт показывает правильный ответ с подсветкой отличий, пользователь отмечает «Знал / Не знал».
- **Сессия** — прогон набора карточек с выбранным режимом и направлением.
- **Прогресс** — счётчики «знал / не знал» по каждой карточке, хранятся в браузере.

## 3. Источники колод (три способа)

1. **Рекомендованные** — список ссылок, захардкоженный в репозитории сайта (`decks.json`). Видны сразу при первом открытии; это материалы автора сайта.
2. **Ссылка** — raw-URL на GitHub (`raw.githubusercontent.com`, CORS открыт). Сайт скачивает текст, кэширует его в localStorage, после чего колода доступна оффлайн. Кнопка «Обновить» перечитывает файл из сети. Поддерживается зеркало jsDelivr (`cdn.jsdelivr.net/gh/...`).
3. **Локальный файл** — выбор файлов с ПК/телефона (мультивыбор: md/txt + лежащие рядом картинки и аудио). Содержимое сохраняется в localStorage, поэтому колода остаётся на сайте после перезагрузки страницы; кнопка «Загрузить заново» подхватывает правки файла с диска. Ограничение: весь localStorage ≈ 5 МБ — тексты колод помещаются свободно, тяжёлые base64-картинки в постоянный кэш не пишутся (живут только в текущей сессии).

Подключать можно сколько угодно колод; одна сессия может гонять несколько колод одновременно.

## 4. Формат базы (актуальна v1.7)

### 4.1 Общие правила

- Один файл = одна колода. Расширения: `.md` (полный синтаксис) и `.txt` (табличный, §4.7).
- Кодировка UTF-8.
- Шапка с метаданными — YAML frontmatter в начале файла, необязательна.
- **Единственный стиль записи** (v1.7): строка с полями через « | » (или Tab) + строки-модификаторы под ней; блочной формы с `front:`/`back:`/`prompt:`/`answer:` больше нет. Строки `---` и пустые строки — визуальные разделители (можно не ставить). Заголовки-секции (первое слово заголовка, любой регистр, русский или английский): `# Карточки`/`# Карты`/`# Card`/`# Cards` — флеш-карты; `# Задания`/`# Задание`/`# Task`/`# Tasks` — задания на ввод; `# Аудио`/`# Произношение`/`# Audio`/`# Speech` — задания на слух. Обычные заголовки (названия уроков) разбор не меняют. Если заголовков нет вообще: строка из двух полей — флеш-карта, из трёх и более — задание.
- Однострочная запись: поля через « | » — сторона 1, сторона 2, затем необязательные подсказка и теги. «;» внутри первых двух полей разделяет варианты, первое значение — каноничное (§4.8). Литеральные « | » и «;» экранируются: `\|`, `\;`.
- Модификаторы (`audio`, `audio1`, `audio2`, `hint`, `tags`, `id`, `direction`, `reverse`) — строки-ключи без « | » под записью; прикрепляются к ближайшей записи выше. Модификатор без записи выше — предупреждение и пропуск строки.
- Разобранные с ошибкой строки не ломают файл: они попадают в предупреждения на плитке колоды.
- Прогресс привязан к тексту карточки: при переписывании текста добавьте поле `id`.

### 4.2 Шапка колоды

```markdown
---
title: Английский A1 — Урок 1. Приветствия
lang: en        # изучаемый язык
base: ru        # язык переводов
reverse: true   # флеш-карты показывать в обе стороны
description: Первая колода: приветствия и знакомство
---
```

### 4.3 Флеш-карты

```markdown
hello | привет
good morning | доброе утро; добрый день
See you tomorrow! | До завтра! | говорится при прощании | приветствия
![](img/dog.jpg) **dog** | собака
Good morning, how are you? | Добрый день, как дела?
hint: формальное приветствие
audio: audio/good-morning.mp3
tags: приветствия
```

Поля через ` | `: сторона A, сторона B, затем необязательные подсказка и теги. `;` в первых двух полях разделяет варианты — первое значение каноничное (§4.8). Литеральные символы экранируются: `\|`, `\;`. Сторона записи может быть картинкой (`![](img/dog.jpg)`).

Поля-модификаторы (§4.1): `hint`, `audio`/`audio1`, `audio2`, `tags`, `id`, `reverse`.

### 4.4 Задания

В секции `# Задания` (и в секции `# Аудио` для обычных записей); 2 поля — минимум, 3-е — подсказка, 4-е — теги:

```markdown
Привет, как дела?; Здравствуйте, как ты? | Hello! How are you?; Hi! How are you? | неформальное приветствие | приветствия
Меня зовут Ана.; Моё имя — Ана | My name is Ana; I am Ana
tags: знакомство
```

- `prompt` — что показываем (текст / картинка); `answer` — эталон. Варианты стороны перечисляются через `;` в её поле (первое значение каноничное, §4.8).
- Для подсветки diff берётся каноничное значение стороны, совпадения с вариантами отмечаются бейджем «Совпадает с эталоном» (§5.3).
- `direction: l2l1 | l1l2 | both` — необязательная фиксация направления. По умолчанию `both`: задание можно переворачивать прямо на сайте; при фиксированном направлении кнопка ⇄ скрыта (§5.3).

### 4.4.1 Секция «Аудио» — задания на слух

Секция `# Аудио`/`# Произношение`/`# Audio`/`# Speech` отделяет задания, связанные только со звуком. Запись начинается с `audio:` или `audio2:` (пометка, чья озвучка), после « | » — текст ответа с вариантами через `;`; далее необязательные подсказка и теги:

```markdown
# Аудио
audio: audio/Hello_Hi.mp3 | Привет ; Здравствуйте
audio2: audio/Привет_Здравствуйте.mp3 | Hello ; Hi
```

- Запись разбирается в задание с пустым текстовым prompt, флагом `audioTask` и направлением `l1l2` (фиксированным — ⇄ скрыт): на показе звучит аудио, пользователь вводит ответ, проверка — канон или вариант.
- Путь аудио хранится в плейлисте стороны prompt (как `audio`), поэтому автоплей при показе задания работает без дополнительных полей; `audio2:`-модификатор под записью добавляет озвучку ответа (звучит после раскрытия).
- id аудиозадания = хэш `audio|путь|ответ` — разные файлы с одинаковым ответом не сливаются в одну запись.
- Строка вида `audio: … | …` вне секции «Аудио» — предупреждение и пропуск (модификатор пишется без « | »). Обычные записи (`текст | текст`) в секции «Аудио» разбираются как задания.

### 4.5 Картинки

Допустимы в любом поле, все три способа:

- `![](img/dog.jpg)` — путь относительно файла колоды; при загрузке по ссылке резолвится от raw-URL;
- `![](https://...)` — внешний хостинг;
- `![](data:image/png;base64,...)` — картинка, вшитая в файл.

При локальной загрузке — мультивыбор файлов или кнопка «Выбрать папку» (input `webkitdirectory`): сайт сам находит в папке .md/.txt и связывает относительные пути в памяти через blob-URL (учитываются и полный относительный путь, и путь без корневой папки, и имя файла). Скрытые файлы (начинающиеся с точки) пропускаются.

На карточке картинка отображается в фиксированном размере: не выше ~170 px по высоте, пропорции сохраняются (`max-width:100%; max-height:170px`). Форматы: png, jpg, webp, gif (в том числе анимированный), svg, bmp — всё, что рендерит браузер; `webm` — видео-контейнер, картинкой не является (для анимации — gif).

### 4.6 Аудио

- `audio` — алиас полного имени `audio1`: озвучка стороны 1 (фронт карточки / prompt задания); `audio2` — озвучка стороны 2 (оборот / answer). Несколько полей `audio`/`audio1` — плейлист, кнопки 🔊 по порядку.
- Пути как у картинок: относительный `audio/good-morning.mp3`, внешний URL.
- Форматы: mp3, ogg, m4a, wav.
- Воспроизведение: при показе стороны с аудио звук проигрывается **один раз автоматически** (при старте упражнения, после оценки — при показе следующего, при перевороте карточки на сторону с аудио, при раскрытии ответа задания); повтор — клавиша `P` или кнопка 🔊 текущей стороны. Автоплей срабатывает ровно один раз на смену стороны и не повторяется при перерисовках; браузеры разрешают его после первого взаимодействия со страницей.
- В карточке аудио-кнопки соответствуют видимой стороне: фронт — `audio`/`audio1`, оборот — `audio2`; в задании под prompt — аудио видимой стороны, после раскрытия ответа добавляются кнопки аудио ответа, если они заданы.
- **Поиск файла при воспроизведении** — цепочка кандидатов: blob-URL из выбранных с колодой файлов (по относительному пути, по пути без корневой папки, по имени) → путь относительно страницы index.html → путь относительно URL колоды (для ссылок на GitHub) → путь как написан. Первый кандидат, который загрузился и начал играть, используется; при ошибке загрузки пробуется следующий, при `NotAllowedError` (браузер запретил автоплей) — тост-подсказка, без перебора. Если ни один не сработал — тост «Аудио недоступно: <путь>».

### 4.7 txt/TSV (массовый ввод)

- Строка, начинающаяся с `#` — комментарий, игнорируется.
- Колонки через Tab: **2 колонки** → флеш-карта (`front<TAB>back`); **3 колонки** → задание (`prompt<TAB>answer<TAB>tags`).
- Варианты перечисляются через `;` прямо в колонке своей стороны (первое значение — каноничное); в задании третья колонка — теги. В .txt нет секций, подсказки и многострочных значений — для этого используйте .md.

### 4.8 Варианты и стороны записи

- У каждой записи две стороны: сторона 1 (`front`/`prompt`) и сторона 2 (`back`/`answer`); язык сторон не фиксируется — сторона 1 не обязана быть русской.
- Варианты перечисляются через `;` прямо в поле своей стороны (первое значение — каноничное). Поля `alt1`/`alt2`/`alt` выведены из формата в v1.7; их место заняли `;`-варианты.
- Проверка ввода (§5.3) принимает канон или любой вариант той стороны, которую пользователь вводит; на флеш-картах варианты показываются строкой «Варианты: …» на своей стороне, в заданиях — «Тоже верно: …» после показа ответа.
- id считается по каноничным значениям сторон, поэтому добавление или правка вариантов не сбрасывает прогресс.

### 4.9 Идентификация карточек и стабильность прогресса

- id карточки = пользовательский `id:` или хэш (front + answer).
- Прогресс привязан к id: правки других карточек прогресс не трогают; правка текста самой карточки без явного `id:` сбрасывает её прогресс — в таком случае стоит указать `id:` явно.

## 5. Тренажёр

### 5.1 Старт сессии

- Выбор одной или нескольких колод, фильтр по тегам.
- Режим: **Карточки** / **Задания** / **Микс** (оба типа вперемешку). Режим фильтрует пул упражнений по типу: в «Заданиях» попадаются только задания с вводом ответа, в «Карточках» — только флеш-карты; «Микс» содержит оба типа.
- Направление: **Смешанно** (случайно на каждую карточку) / **Изучаемый → родной** / **Родной → изучаемый**.
- Режим «Повторить ошибки» — только карточки со счётчиком «не знал» > 0.
- Ограничение сессии по количеству карточек (по умолчанию — вся колода).

### 5.2 Флеш-карта

- Показ стороны A → **тап на телефоне / клик мышью / пробел** — переворот.
- Кнопка «Подсказка» — показывает текст поля `hint` (если задан).
- Кнопка аудио текущей стороны; автоплей стороны — один раз при её показе (§4.6).
- Самооценка, две кнопки: **«Знал»** (клавиша `1`) и **«Не знал»** (клавиша `2`).

### 5.3 Задание

- Показ prompt + поле ввода; `Enter` или кнопка — «Показать ответ».
- **Кнопка «Подсказка»**: каждое нажатие открывает одну ещё закрытую букву ответа в случайной позиции; закрытые буквы показываются как «•»; пробелы и знаки (`¿`, `¡`, `.`, `,`) видны сразу — они помогают держать структуру фразы. Число нажатий пишется в статистику.
- Показ ответа: эталон + пословная подсветка diff — совпавшие слова зелёным, отличающиеся красным. При сравнении регистр, знаки `¿?¡!.`,`,`, ё/е и ударения не учитываются. Варианты вводимой стороны перечисляются строкой «Тоже верно: …»; совпадение ввода с каноном или любым вариантом отмечается зелёным бейджем «Совпадает с эталоном» (§4.8).
- **Кнопка «⇄»** — переворот направления текущего задания на ходу: пользователь составил задание ru→en, захотел en→ru — переворачивает кнопкой, файл править не нужно. Кнопка скрыта (и клавиша `F` игнорируется с тостом), если направление зафиксировано полем `direction` или это задание из секции «Аудио».
- Самооценка: «Знал» / «Не знал».

### 5.4 Горячие клавиши (ПК)

| Клавиша | Действие |
| --- | --- |
| Пробел / Enter | Переворот карточки или «Показать ответ» |
| 1 | Знал |
| 2 | Не знал |
| H | Подсказка |
| P | Повторить аудио текущей стороны |
| F | Перевернуть направление задания |
| Esc | Выйти из сессии |

Обработка через `e.code` (физическая клавиша) — хоткеи работают на любой раскладке, включая русскую.

### 5.5 Прогресс

- localStorage по ключу «колода + id карточки»: счётчики знал/не знал, дата последнего показа, использованные подсказки. Дата в схеме — задел под будущий SRS без миграции данных.
- Экспорт и импорт прогресса JSON-файлом — перенос между ПК и телефоном.
- Статистика по колоде: всего / знаю / ошибки; сброс прогресса кнопкой.

## 6. Интерфейс

- Сборка: **один самодостаточный файл `index.html`** (CSS и JS внутри, без шага сборки). Тренажёр и инструкция — два экрана одного приложения с hash-навигацией (`#/`, `#/instruction`, `#/session`); демо-колода вшита в файл и работает без интернета.
- Инструкция — отдельный экран с сайдбар-навигацией по разделам, якорными ссылками и копируемыми примерами (§7).
- Язык интерфейса: русский по умолчанию + переключатель на English, выбор сохраняется.
- Шрифт интерфейса — моноширинный (стек `ui-monospace → Cascadia Mono → SF Mono → Menlo → Consolas → DejaVu Sans Mono → monospace`), все размеры текста заданы в rem от базы `html{font-size:16px}`.
- **Размер шрифта** — селектор 85 / 100 / 115 / 130 / 150 %: в блоке «Настройки» на главной **и рядом с карточками в шапке сессии** (справа от названия колоды); выбор хранится в localStorage и применяется к базе rem при запуске, масштабируется весь интерфейс, включая кодбоксы инструкции.
- Мобильная вёрстка: крупные кнопки под большой палец, тап по всей карточке, всё помещается без горизонтального скролла.
- Горячие клавиши на ПК (§5.4).

## 7. Страница инструкции — содержание

1. **Быстрый старт за 5 минут** — готовый шаблон колоды целиком, кнопка «Скопировать».
2. **Формат базы** — шапка, секции `# Карточки` / `# Задания`, однострочные записи с вариантами через `;`, блочные записи, `alt1`/`alt2`, все поля, правила разделения и экранирования.
3. **Картинки** — три способа + как загружать локально с картинками.
4. **Аудио**:
   - поля `audio`/`audio1` и `audio2`, где их писать (блоком или модификатором под однострочником), плейлист, автоплей один раз и повтор по `P`;
   - **как создать свои аудио**:
     - **edge-tts** (рекомендуемый способ): бесплатно, нейроголоса Microsoft, десятки языков. Пример: `edge-tts --voice en-US-AriaNeural --text "Hello! How are you?" --write-media audio/hello-how-are-you.mp3`;
     - **gTTS** — простые Google-голоса, короткий Python-скрипт;
     - **Piper** — локальный оффлайн-синтез, быстрый, без интернета;
     - **Forvo** — живые записи носителей для отдельных слов;
     - платные сервисы максимального качества: Azure TTS, ElevenLabs, OpenAI TTS;
     - обычная запись голоса на телефоне;
   - заметка: позже в репозиторий добавим скрипт батч-генерации, который прочитает md-колоду и создаст mp3 для всех карточек сразу.

## 8. Архитектура и репозиторий

```
repo/
  index.html          # весь сайт: тренажёр + инструкция (CSS/JS внутри)
  decks/
    en-a1-u1.md       # пример колоды
    fr-basics.txt     # пример TSV-колоды
    img/…             # картинки для колод
    audio/…           # аудио для колод
  README.md
```

- Рекомендованные колоды задаются массивом `RECOMMENDED_DECKS` в начале скрипта внутри index.html (автор сайта редактирует список ссылок).

- Хостинг: GitHub Pages. Сборка не нужна.
- Загрузка по ссылке: `fetch` на raw-URL (CORS открыт у `raw.githubusercontent.com` и `cdn.jsdelivr.net`).
- localStorage (~5 МБ): список подключённых источников, кэш текстов колод, прогресс, настройки. base64-картинки и blob-объекты в постоянный кэш не пишутся.
- Модули: `parser.js` (md/txt → колода), `storage.js` (кэш и прогресс), `session.js` (режимы, направление, подсказки), `ui.js` (рендер, hotkeys), `i18n.js` (RU/EN).

## 10. Хронология решений

- **v1.0**: гибрид-синтаксис (строчно + блоком); один файл-урок с секциями; проверка самооценкой; оба направления; картинки всеми тремя способами; простой прогресс без SRS; raw-ссылки + кэш; интерфейс RU + EN.
- **v1.1**: ключи полей только английские; кнопка «Подсказка» в заданиях — открывает случайные буквы по одной; самооценка из двух кнопок; микс-режим с первого дня; локальные колоды сохраняются в localStorage; поле `audio:` и плеер; отдельная страница инструкции с навигацией; переворот направления задания на сайте кнопкой «⇄»; переворот карточки тапом/кликом/пробелом.
- **v1.2 (реализация)**: сборка сведена к одному самодостаточному index.html (тренажёр + инструкция + вшитая демо-колода); уточнено правило разбиения карточек — новая карточка также начинается после пустой строки перед `front:`/`prompt:`, короткие карточки идут по одной на строку; строки-шорткаты перед блочной карточкой тоже разбираются как карточки. Подтверждено тестами: 42 юнит-теста парсера и браузерный прогон (сессия, подсказка-буквы, diff, ⇄, EN, мобильная вёрстка 375px без переполнений).
- **v1.3**: изучаемый язык в демо-колоде, примерах инструкции и файле-примере заменён с испанского на английский (переводы остаются русскими); id демо-колоды — `builtin:demo-en`, при первом запуске новой версии старая испанская демо-колода автоматически удаляется и заменяется английской.
- **v1.4**: исправлен баг режима сессии — выбор «Задания» не фильтровал пул упражнений, поэтому в сессии появлялись флеш-карты; теперь режим строго фильтрует по типу. Шрифт интерфейса переведён на моноширинный; добавлена настройка размера шрифта (85–150 %, хранится в localStorage, весь интерфейс на rem-базе).
- **v1.5**: симметричные варианты ответа `alt1`/`alt2` — принимается вариант той стороны, которую пользователь вводит (после ⇄ тоже), варианты показываются на своей стороне карточки и в строке «Тоже верно». Однострочные записи расширены: в секциях работают 3–4 поля (подсказка, теги) и `;`-варианты в обеих сторонах; в .txt `;`-варианты тоже в обеих колонках. Секции `# Карточки`/`# Задания` стали управляющими: задают тип однострочных записей. Блочные `prompt`/`answer` больше не разрезаются по `;` (эскейп-хэтч для текста с «;»); порядок «блоки + однострочники вперемешку» сохраняется. Демо-колода и файл-пример переведены на новый синтаксис; id всех записей не изменились — прогресс сохраняется.
- **v1.6**: медиа-поля сторон и удобства сессии. (1) Аудио: `audio` = алиас `audio1` — озвучка стороны 1, `audio2` — стороны 2; звук проигрывается автоматически **один раз** при показе стороны (старт/оценка/переворот/раскрытие ответа) без настройки-переключателя, повтор — клавиша `P` и кнопки 🔊 по сторонам; модификаторы `audio:`/`audio2:`/`hint:`/`tags:`/`alt1:`/`alt2:` и другие необязательные поля можно дописывать строкой под однострочной записью (прикрепляются к ближайшей записи выше), блок может начинаться с `audio:` (задание-аудирование). (2) Хоткеи подтверждены на `e.code` — работают на любой раскладке. (3) Селектор размера шрифта продублирован в шапке сессии рядом с карточками. (4) Картинки на карточке фиксируются по высоте (~170 px). (5) Кнопка «Выбрать папку» рядом с «Выбрать файлы»: загрузка целой папки с колодами и медиа, пути связываются по относительному пути/имени; скрытые файлы пропускаются. Подтверждено тестами: 80 юнит-тестов парсера, id записей файла-примера не изменились.
- **v1.7**: один стиль записи (решение заказчика — «несколько стилей неудобны»). (1) Блочные записи (`front:`/`back:`/`prompt:`/`answer:`) и поля вариантов `alt1`/`alt2`/`alt` выведены из формата: любая запись — строка с « | », варианты — через `;` в обеих сторонах, длинные тексты и «;» в тексте — через экранирование `\;` / `\|`. Демо-колода и файл-пример переведены на новый стиль; все 40 id записей сохранены (прогресс пользователей не сбрасывается), что зафиксировано скриптом `check_ids.js` со списком ожидаемых id. (2) Секции переименовываются по первому слову заголовка в любом регистре, русский/английский: Карточки/Карты/Card(s), Задания/Задание/Task(s), Аудио/Произношение/Audio/Speech. (3) Новая секция «Аудио» — задания на слух: запись `audio: путь | ответ`, путь хранится в плейлисте prompt-стороны, направление зафиксировано, ⇄ скрыт, id = хэш `audio|путь|ответ`. (4) Исправлено «Аудио недоступно», которое показывалось при каждом проигрывании локальной колоды без выбранных медиа: теперь путь ищется по цепочке (blob из выбранных файлов → рядом с index.html → от URL колоды → как написано) до первого успешного запуска, ошибка загрузки пробует следующий кандидат, `NotAllowedError` показывает отдельную подсказку, а финальный тост называет путь файла. (5) Инструкция (RU/EN) переписана под один стиль, секции-алиасы и секцию «Аудио». Тесты: 67 юнит-тестов парсера.
