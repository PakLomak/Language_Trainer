# Языковой тренажёр «Карточки» — спецификация v1.6

Дата: 2026-11-22. Статус: внедрено в index.html (формат v1.12 — реверс на двух языках «reverse» / «поворот»; оценка ✓ / ✗; вшитая колода «Test»; медиа колоды по ссылке с GitHub; теги-подзаголовки «## …»; автосвязка аудио понимает апострофы («I’ll» = «Ill»), «чужой» файл не приклеивается к свободной стороне, подробный журнал аудио с подсказками переименования и записями без файла; новая главная: «Настройки» строками, иконки загрузки, «Медиа» под загрузкой, журнал на всю ширину мелким шрифтом).

---

## 1. Что это

Статический сайт (GitHub Pages, без бэкенда) для заучивания слов и фраз: флеш-карты и задания на перевод с вводом ответа. Базы пользователи делают сами в txt/md и подключают тремя способами (§3). Автор сайта размещает на нём ссылки на свои рекомендованные материалы; свои базы любой пользователь загружает со своего устройства.

Принципы:

- Без сервера: всё работает в браузере, данные хранятся в localStorage.
- Без сборки: vanilla HTML/CSS/JS, два html-файла.
- База — обычный текстовый файл, который правится в любом редакторе.
- Телефон — основной сценарий: крупные кнопки, тап по всей карточке.

## 2. Сущности

- **Колода** — один файл `.md` или `.txt`, содержит флеш-карты и/или задания.
- **Флеш-карта** — сторона A (слово / фраза / предложение / картинка / аудио) и сторона B (перевод или расшифровка на родном языке).
- **Задание** — `prompt` (что показываем) и `answer` (что нужно написать). Проверка — самооценкой: сайт показывает правильный ответ с подсветкой отличий, пользователь отмечает «Знал / Не знал».
- **Сессия** — прогон набора карточек с выбранным режимом и направлением.
- **Прогресс** — счётчики «знал / не знал» по каждой карточке, хранятся в браузере.

## 3. Источники колод (три способа)

1. **Рекомендованные** — список ссылок, захардкоженный в репозитории сайта (`decks.json`). Видны сразу при первом открытии; это материалы автора сайта.
2. **Ссылка** — raw-URL на GitHub (`raw.githubusercontent.com`, CORS открыт). Сайт скачивает текст, кэширует его в localStorage, после чего колода доступна оффлайн. Кнопка «Обновить» перечитывает файл из сети. Поддерживается зеркало jsDelivr (`cdn.jsdelivr.net/gh/...`).
3. **Локальный файл** — выбор файлов с ПК/телефона (мультивыбор: md/txt + лежащие рядом картинки и аудио, либо сразу .zip-архив). Содержимое сохраняется в localStorage, поэтому колода остаётся на сайте после перезагрузки страницы; кнопка «Загрузить заново» подхватывает правки файла с диска. Ограничение: весь localStorage ≈ 5 МБ — тексты колод помещаются свободно, тяжёлые base64-картинки в постоянный кэш не пишутся (живут только в текущей сессии).

Подключать можно сколько угодно колод; одна сессия может гонять несколько колод одновременно.

### 3.1 Медиа-библиотека (аудио и картинки)

Единый механизм подключения медиа пользователя: **выкладывать mp3 и картинки в репозиторий не нужно** — пользователь сам подгружает свои файлы с устройства, и они работают для всех колод, включая колоды, подключённые по ссылке.

- **Три способа подключения** (кнопки в блоке «Загрузить файлы с устройства»):
  - «Выбрать файлы» — мультивыбор: колоды .md/.txt вместе с медиа рядом, или сразу .zip-архив;
  - «Выбрать папку» — input `webkitdirectory`, целая папка: колоды и медиа внутри находятся автоматически;
  - «Загрузить архив» — .zip: колоды .md/.txt внутри импортируются как локальные колоды, аудио и картинки распаковываются в память.
- **Предзагрузка**: при выборе источника все его медиа (аудио и картинки) **целиком индексируются сразу** — каждый файл получает blob-URL и ключи в общем индексе; счётчик найденных файлов показывается тостом и на главной в панели «Медиа-библиотека». Дальнейшее воспроизведение и показ идут из памяти: без сетевых запросов, без задержек, без 404. Библиотека живёт до перезагрузки страницы; кнопка «Очистить» освобождает память досрочно (v1.11: сбрасывает и кеш «Аудио недоступно»).
- **Сопоставление имён** (единое для `audio:` и `![]()`): путь из колоды ищется в индексе по цепочке — точный относительный путь → путь без корневой папки → имя файла → то же имя без учёта регистра. Префикс папки в пути не важен: `audio/hello.mp3` найдётся и как `hello.mp3` (форма с префиксом сохранена для совместимости со старыми колодами). Кириллица и пробелы в именах файлов работают (подключение идёт с диска, без сетевого кодирования URL); всё, кроме регистра, должно совпадать посимвольно — регистр соблюдать желательно, регистронезависимый поиск — страховка.
- **Скрытые файлы** (начинаются с точки), мусор macOS-архивов (`__MACOSX/`, `._…`) и служебные файлы (`.md/.txt/.json` — к медиа не относятся) пропускаются.
- **ZIP-архивы**: методы «без сжатия» (stored) и deflate — то, что пишут все архиваторы. **Кириллица в именах**: имя с меткой UTF-8 (0x0800) читается как UTF-8; без метки кодировка определяется автоматически — кандидаты (UTF-8, cp1251, cp866, koi8-r) оцениваются по доле «настоящей» кириллицы с бонусом за строчные, побеждает лучший (байты cp866, прочитанные как cp1251, дают псевдографику и проигрывают). После загрузки тост показывает первые имена файлов — кодировку видно сразу. Зашифрованные архивы и ZIP64 не поддерживаются (внятная ошибка). Нужен браузер с `DecompressionStream` — свежие Chrome/Edge/Firefox; иначе подсказка выбрать папку. Другие форматы архивов (.7z, .rar) сознательно не поддерживаются — тяжёлые wasm-библиотеки для однофайлого сайта (§9).
- **Поиск файла при воспроизведении** — цепочка: медиа, выбранное вместе с этой колодой → **медиа-библиотека** → путь относительно страницы index.html → путь относительно URL колоды (для ссылок) → путь как написан. Первый рабочий кандидат используется.
- **Тихие ошибки**: файл, которого нет ни в библиотеке, ни рядом, помечается один раз — тост «Аудио недоступно: <путь>» (повторы одного пути не спамят), битая картинка на карточке заменяется тихой пометкой «🖼 картинка недоступна» без ломания карточки.

## 4. Формат базы (актуальна v1.12; v1.12 — теги-подзаголовки «## Тег», апострофы в автосвязке аудио, подробный журнал аудио)

### 4.1 Общие правила

- Один файл = одна колода. Расширения: `.md` (полный синтаксис) и `.txt` (табличный, §4.7).
- Кодировка UTF-8.
- Шапка с метаданными — YAML frontmatter в начале файла, необязательна.
- **Единственный стиль записи** (v1.7): строка с полями через « | » (или Tab) + строки-модификаторы под ней; блочной формы с `front:`/`back:`/`prompt:`/`answer:` больше нет. Строки `---` и пустые строки — визуальные разделители (можно не ставить). Заголовки-секции (первое слово заголовка, любой регистр, русский или английский): `# Карточки`/`# Карты`/`# Card`/`# Cards` — флеш-карты; `# Задания`/`# Задание`/`# Task`/`# Tasks` — задания на ввод; `# Аудио`/`# Произношение`/`# Audio`/`# Speech` — задания на слух. Обычные заголовки разбор не меняют, но заголовок уровня **## и глубже** (не секция) становится тегом для всех записей ниже — до следующего заголовка (v1.12): теги перечисляются через запятую, собственные `tags:` записи добавляются к тегу подзаголовка (дубликаты снимаются без учёта регистра). Одиночный `#` и заголовки-секции тегами не становятся. Если заголовков нет вообще: строка из двух полей — флеш-карта, из трёх и более — задание.
- Однострочная запись: поля через « | » — сторона 1, сторона 2, затем необязательные подсказка и теги. «;» внутри первых двух полей разделяет варианты, первое значение — каноничное (§4.8). Литеральные « | » и «;» экранируются: `\|`, `\;`.
- Модификаторы (`audio`, `audio1`, `audio2`, `hint`, `tags`, `id`, `direction`, `reverse`) — строки-ключи без « | » под записью; прикрепляются к ближайшей записи выше. Модификатор без записи выше — предупреждение и пропуск строки.
- **Направление изучения определяется шапкой и текстами, а не позицией столбцов** (v1.10): `lang` — изучаемый язык, `base` — базовый (родной); сторона языка каждой записи распознаётся по алфавиту, поэтому записи можно писать в любом порядке столбцов — «Базовый → Изучаемый» всегда показывает базовую сторону (§5.1). Реверс включается в шапке на двух языках — `reverse: true` или `поворот: разрешен` — и выключается `reverse: false` / `поворот: запрещен` (в шапке или у отдельной карточки); при `lang == base` колода грамматическая — реверс выключается сам. Без реверса задания идут в одну сторону «Базовый → Изучаемый», как и карточки — «Изучаемый → Базовый».
- Разобранные с ошибкой строки не ломают файл: они попадают в предупреждения на плитке колоды.
- Прогресс привязан к тексту карточки: при переписывании текста добавьте поле `id`.

### 4.2 Шапка колоды

```markdown
---
title: Gap Fill Be forms
lang: en        # изучаемый язык
base: ru        # родной язык; если совпадает с lang — колода грамматическая, реверс выключается сам
reverse: true   # или «поворот: разрешен» (по-русски); false/запрещен — реверс выключить (по умолчанию выключен)
description:
---
```

Семантика шапки (v1.10):

- `lang` — **изучаемый** язык, `base` — **родной** (язык переводов). Оба кода необязательны; они определяют направление «Родной → изучаемый», язык голоса синтеза речи (§5.6) и показываются в настройке сессии строкой «изучаемый en · родной ru».
- `reverse` (или по-русски `поворот`) — реверс всей колоды: `true` («разрешен») — обе стороны для карточек и заданий, в сессию попадают оба направления; `false` («запрещен») или отсутствие поля — только в одну: карточки «видно изучаемый → вспомнить базовый», задания «видно базовый → вписать изучаемый» (v1.11: раньше задания по умолчанию шли в обе стороны).
- `lang == base` (например, оба `en`) — **грамматическая колода**: реверс выключается принудительно (даже при `reverse: true`), задания идут «вопрос → ответ», вариант направления в настройке сессии недоступен (чип притушен).
- Реверс можно запрещать точечно — модификатором `reverse: false` под конкретной карточкой (§4.3): карточка тренируется в одном направлении, кнопка ⇄ и клавиша `F` у неё не работают, под карточкой видна пометка «Реверс отключён — доступен только один вариант».

### 4.3 Флеш-карты

```markdown
hello | привет
good morning | доброе утро; добрый день
See you tomorrow! | До завтра! | говорится при прощании | приветствия
![](img/dog.jpg) **dog** | собака
Good morning, how are you? | Добрый день, как дела?
hint: формальное приветствие
audio: audio/good-morning.mp3
tags: приветствия
```

Поля через ` | `: сторона A, сторона B, затем необязательные подсказка и теги. `;` в первых двух полях разделяет варианты — первое значение каноничное (§4.8). Литеральные символы экранируются: `\|`, `\;`. Сторона записи может быть картинкой (`![](img/dog.jpg)`).

Поля-модификаторы (§4.1): `hint`, `audio`/`audio1`, `audio2`, `tags`, `id`, `reverse`.

`reverse` (или `поворот`) под карточкой запрещает/разрешает реверс только ей — даже при `reverse: true` в шапке. Значения: `true`/`false`, `yes`/`no`, `да`/`нет`, `1`/`0` и русские слова `разрешен`/`разрешён`/`включен`/`вкл` ↔ `запрещен`/`запрещён`/`выключен`/`выкл` («ё» приводится к «е»); непонятное значение считается незаданным (действует шапка).

### 4.4 Задания

В секции `# Задания` (и в секции `# Аудио` для обычных записей); 2 поля — минимум, 3-е — подсказка, 4-е — теги:

```markdown
Привет, как дела?; Здравствуйте, как ты? | Hello! How are you?; Hi! How are you? | неформальное приветствие | приветствия
Меня зовут Ана.; Моё имя — Ана | My name is Ana; I am Ana
tags: знакомство
```

- `prompt` — что показываем (текст / картинка); `answer` — эталон. Варианты стороны перечисляются через `;` в её поле (первое значение каноничное, §4.8).
- Для подсветки diff берётся каноничное значение стороны, совпадения с вариантами отмечаются бейджем «Совпадает с эталоном» (§5.3).
- `direction: l2l1 | l1l2 | both` — необязательная фиксация направления. По умолчанию `both`: задание можно переворачивать прямо на сайте; при фиксированном направлении кнопка ⇄ скрыта (§5.3). В грамматической колоде (`lang == base`) задание без `direction` идёт в одном направлении «вопрос → ответ».
- **Задание с картинкой** (v1.10): запись `![](img/dog.jpg) | Dog` показывает картинку и поле ввода — вписать, что изображено. У такого задания направление всегда одно (картинка — вопросом), кнопки ⇄ нет, подсказка открывает буквы ответа. Картинка, случайно попавшая в поле ответа, меняется местами с текстом (предупреждение в журнале); запись, где обе стороны — картинки, пропускается с предупреждением.

```markdown
# Задания
![](img/dog.jpg) | Dog ; Puppy

![](img/cat.jpg) | Cat
hint: домашнее животное
```

### 4.4.1 Секция «Аудио» — задания на слух

Секция `# Аудио`/`# Произношение`/`# Audio`/`# Speech` отделяет задания, связанные только со звуком. Запись начинается с `audio:` или `audio2:` (пометка, чья озвучка), после « | » — текст ответа с вариантами через `;`; далее необязательные подсказка и теги:

```markdown
# Аудио
audio: audio/Hello_Hi.mp3 | Привет ; Здравствуйте
audio2: audio/Привет_Здравствуйте.mp3 | Hello ; Hi
```

- Запись разбирается в задание с пустым текстовым prompt, флагом `audioTask` и направлением `l1l2` (фиксированным — ⇄ скрыт): на показе звучит аудио, пользователь вводит ответ, проверка — канон или вариант.
- Путь аудио хранится в плейлисте стороны prompt (как `audio`), поэтому автоплей при показе задания работает без дополнительных полей; `audio2:`-модификатор под записью добавляет озвучку ответа (звучит после раскрытия).
- id аудиозадания = хэш `audio|путь|ответ` — разные файлы с одинаковым ответом не сливаются в одну запись.
- Строка вида `audio: … | …` вне секции «Аудио» — предупреждение и пропуск (модификатор пишется без « | »). Обычные записи (`текст | текст`) в секции «Аудио» разбираются как задания.

### 4.5 Картинки

Допустимы в любом поле, все три способа:

- `![](img/dog.jpg)` — путь относительно файла колоды; при загрузке по ссылке резолвится от raw-URL;
- `![](https://...)` — внешний хостинг;
- `![](data:image/png;base64,...)` — картинка, вшитая в файл.

При локальной загрузке (§3.1): «Выбрать папку» или «Загрузить архив» — сайт предзагружает все картинки в медиа-библиотеку и связывает их по относительному пути, а если точного совпадения нет — по имени файла. Библиотека обслуживает все колоды, включая колоды по ссылке: колода может лежать на GitHub, а картинки — на диске пользователя. Картинки, которых нет в библиотеке, не ломают карточку — на их месте тихая пометка «картинка недоступна».

На карточке картинка отображается в фиксированном размере: не выше ~170 px по высоте, пропорции сохраняются (`max-width:100%; max-height:170px`). Форматы: png, jpg, webp, gif (в том числе анимированный), svg, bmp — всё, что рендерит браузер; `webm` — видео-контейнер, картинкой не является (для анимации — gif).

### 4.6 Аудио: порядок поиска звука

- `audio` — алиас полного имени `audio1`: озвучка стороны 1 (фронт карточки / prompt задания); `audio2` — озвучка стороны 2 (оборот / answer). Несколько полей `audio`/`audio1` — плейлист, кнопки 🔊 по порядку. Пути как у картинок: относительный `audio/good-morning.mp3`, внешний URL. Форматы: mp3, ogg, m4a, wav и другие браузерные.
- Для каждой стороны карточки/задания сайт ищет звук в этом порядке — **первый найденный шаг и работает**:
  1. **Строки `audio:`/`audio1:`/`audio2:`** — ручное указание, главный источник; путь ищется по цепочке (§4.6 «Поиск файла» ниже);
  2. **Нумерованный файл `NN_текст.ext`** — номер находит запись, текст в имени решает, чья это сторона (§4.6.1);
  3. **Файл только с номером `NN.ext`** — общая озвучка карточки, играет на обеих сторонах (§4.6.1);
  4. **Файл по имени без номера** — `Hello_Hi.mp3` для карточки «Hello ; Hi»; тексты до 6 слов (§4.6.1);
  5. **Синтез речи браузера** — если включён (§5.6) и файла нет.
- Воспроизведение: при показе стороны звук проигрывается **один раз автоматически** (старт упражнения, оценка → следующая карточка, переворот, раскрытие ответа); повтор — клавиша `P` или кнопка 🔊 текущей стороны. Кнопка 🔊 под карточкой есть и когда файла нет: тогда она читает текст синтезом речи (§5.6).
- **Поиск файла по пути** (для строк `audio:`) — цепочка кандидатов: blob из выбранных с колодой файлов → **медиа-библиотека (§3.1)** → путь относительно index.html → путь относительно URL колоды → путь как написан. Первый кандидат, который загрузился и начал играть, используется; при `NotAllowedError` — тост-подсказка; если ни один не сработал — тост «Аудио недоступно: <путь>» один раз на путь.

#### 4.6.1 Автосвязка файлов по нумерации и имени

Записи пронумерованы при разборе: **карточки — с 01 отдельно, задания — отдельно, аудиозадания секции # Аудио — отдельно**; счёт по порядку появления, строки-модификаторы (`hint:`, `tags:`, `audio:`…) не считаются. Нумерация не пишется в файл — это внутренние номера для связи с медиа.

- **`NN_текст.ext`** — номер (цифры до первого подчёркивания; `1` и `01` равнозначны, после 99 — просто `100`) находит запись с этим номером, **текст после номера решает, чья это сторона**: совпал с текстом стороны 1 (с учётом `;`-вариантов) — озвучка стороны 1, с текстом стороны 2 — стороны 2. Поэтому карточки можно записывать в любом порядке (`English | Русский` или `Русский | English`) и тренировать в обе стороны — привязка идёт к тексту, не к позиции.
- Сравнение текста с именем: регистр, подчёркивания/дефисы и пунктуация не важны (`How_are_you` = «How are you?»); достаточно **словесного начала текста** (`01_Hello.mp3` подойдёт для «Hello ; Hi ; Hey»). **Апострофы удаляются без пробела** (v1.12): «I’ll be back soon.» = `Ill_be_back_soon`, «don’t» = `dont` — в именах файлов апострофов не бывает (раньше апостроф превращался в пробел и такие файлы никогда не находили пару); на проверку вводимых ответов это не влияет — «dont» вместо «don’t» в задании остаётся ошибкой.
- **`NN.ext` без текста** — общая озвучка записи №NN: прикрепляется к карточке №NN и играет на обеих её сторонах. Карточка «перебивает» задание при одинаковом номере: файлы для заданий называйте с текстом (`01_Привет_как_дела.mp3`).
- **Имя без номера** связывается с записью, чей полный текст (с вариантами) равен имени, при длине текста **до 6 слов** (`Goodbye_Bye.mp3` для «Goodbye ; Bye»). Длинные предложения — нумерацией или строками `audio:`.
- **Приоритет колод**: файлы потребляются глобально — сначала пользовательские колоды, встроенные (демо) последними; демо-колода не претендует на нумерованные файлы вовсе (только текстовые совпадения). Текстовая привязка — доказательство принадлежности.
- **Cohort — «файлы своего источника»**: колода запоминает источник загрузки (корень выбранной папки / имя zip-архива / метка мультивыбора), медиа-файлы несут ту же метку. Нумерованный файл, приехавший вместе с колодой, приоритетнее для неё, чем файл соседней колоды, у которой совпал лишь номер записи; непарные файлы показываются на плитке именно колоды-владельца источника.
- **Устойчивость импорта**: ошибка разбора одной колоды не прерывает загрузку остальных и медиа (частичная ошибка видна в тосте), медиа-библиотека обновляется на экране всегда.
- **Остаточный принцип**: у номера ровно один файл без текстового совпадения, при том что другая сторона этой записи уже получила файл по тексту — файл встаёт на свободную сторону. Если же текст файла узнаётся в **другой** записи (в любой колоде), файл «чужой»: на свободную сторону он не встаёт и попадает в отчёт с подсказкой переименования (v1.12; переставленные варианты и вольные подписи допустимы — точный префикс не требуется).
- **Подробный журнал аудио** (v1.12, вместо строки на плитке): по каждой колоде журнал перечисляет файлы без пары — с подсказкой, чей это текст и как переименовать (`04_Put_some_sugar_in.mp3 — похоже, это запись №2 «Put some sugar in», переименуйте в 02_Put_some_sugar_in.mp3`; если на записи уже есть файл с правильным номером — пометка «похоже, дубль») — и записи без файла (`№5 «Did you start streaming already?» — файла нет, ожидается 05_did_you_start_streaming_already.mp3`; только у колод, к которым аудио подключалось). Файлы с ручными строками `audio:` в отчёт не попадают; файлы без номера и с неузнанным текстом перечисляются с причиной. Картинки автосвязкой не подбираются — только явные `![]()`-ссылки (§4.5).

### 4.7 txt/TSV (массовый ввод)

- Строка, начинающаяся с `#` — комментарий, игнорируется.
- Колонки через Tab: **2 колонки** → флеш-карта (`front<TAB>back`); **3 колонки** → задание (`prompt<TAB>answer<TAB>tags`).
- Варианты перечисляются через `;` прямо в колонке своей стороны (первое значение — каноничное); в задании третья колонка — теги. В .txt нет секций, подсказки и многострочных значений — для этого используйте .md.

### 4.8 Варианты и стороны записи

- У каждой записи две стороны: сторона 1 (`front`/`prompt`) и сторона 2 (`back`/`answer`); язык сторон не фиксируется — сторона 1 не обязана быть русской.
- Варианты перечисляются через `;` прямо в поле своей стороны (первое значение — каноничное). Поля `alt1`/`alt2`/`alt` выведены из формата в v1.7; их место заняли `;`-варианты.
- Проверка ввода (§5.3) принимает канон или любой вариант той стороны, которую пользователь вводит; на флеш-картах варианты показываются строкой «Варианты: …» на своей стороне, в заданиях — «Тоже верно: …» после показа ответа.
- id считается по каноничным значениям сторон, поэтому добавление или правка вариантов не сбрасывает прогресс.

### 4.9 Идентификация карточек и стабильность прогресса

- id карточки = пользовательский `id:` или хэш (front + answer).
- Прогресс привязан к id: правки других карточек прогресс не трогают; правка текста самой карточки без явного `id:` сбрасывает её прогресс — в таком случае стоит указать `id:` явно.

## 5. Тренажёр

### 5.1 Старт сессии

- Выбор одной или нескольких колод, фильтр по тегам.
- Режим: **Карты** / **Задания** (v1.11 — «Микс» убран как ненужный). Режим фильтрует пул упражнений по типу: в «Заданиях» попадаются только задания с вводом ответа, в «Картах» — только флеш-карты.
- Направление: **Базовый → Изучаемый** / **Изучаемый → Базовый** (v1.11 — «Смешанно» убрано: языки колода уже заявляет в шапке, поэтому направление всегда конкретное; вариант, недоступный в выбранном режиме, притушен, а при полном отсутствии направлений строка направления скрыта).
- **Направление идёт за языками, а не за столбцами** (v1.10): в настройке сессии показываются языки выбранных колод («Базовый: ru · Изучаемый: en», для грамматики — «en — грамматика (lang = base)»). «Базовый → Изучаемый» всегда показывает базовую сторону: если в файле русский слева, а английский справа — первой всё равно появится русская сторона. Сторона языка записи распознаётся по алфавиту текста и шапке колоды; у колод без шапки работает прежнее поведение (столбец 1 показывается первым).
- **Недоступные варианты притушены** (по выбранному режиму): если у колод в режиме «Карты»/«Задания» реверс выключен (`reverse: false` / `поворот: запрещен`, `lang = base`) — недоступный чип направления неактивен, доступен единственный; если реверс есть не у всех колод — под чипами строка-пояснение. Выбор направления, не имеющего в колоде упражнений, даёт тост «Не нашлось ни одной карточки».
- Режим «Повторить ошибки» — только карточки со счётчиком «не знал» > 0.
- Ограничение сессии по количеству карточек (по умолчанию — вся колода).

### 5.2 Флеш-карта

- Показ стороны A → **тап на телефоне / клик мышью / пробел** — переворот.
- **Переворот — анимация 0,5 с** в обе стороны (новая грань «входит» 3D-поворотом); при `prefers-reduced-motion` анимация отключается.
- Кнопка «Подсказка» — показывает текст поля `hint` (если задан).
- Кнопка аудио текущей стороны; автоплей стороны — один раз при её показе (§4.6).
- **Пометка «Реверс отключён — доступен только один вариант»** (v1.10) — под карточками, которым реверс запрещён (`reverse: false` у карточки или в шапке, грамматическая колода); кнопка ⇄ и клавиша `F` у них игнорируются с тостом «Реверс отключён: у этой карточки один вариант».
- Самооценка — две крупные кнопки **✓** и **✗** (v1.11: знаки вместо слов «Знал» / «Не знал»; подпись — в подсказке кнопки и в `aria-label`; клавиши `1` и `2` прежние).

### 5.3 Задание

- Показ prompt + поле ввода; `Enter` или кнопка — «Показать ответ».
- **Кнопка «Подсказка»**: каждое нажатие открывает одну ещё закрытую букву ответа в случайной позиции; закрытые буквы показываются как «•»; пробелы и знаки (`¿`, `¡`, `.`, `,`) видны сразу — они помогают держать структуру фразы. Число нажатий пишется в статистику.
- Показ ответа: эталон + пословная подсветка diff — совпавшие слова зелёным, отличающиеся красным. При сравнении регистр, знаки `¿?¡!.`,`,`, ё/е и ударения не учитываются. Варианты вводимой стороны перечисляются строкой «Тоже верно: …»; совпадение ввода с каноном или любым вариантом отмечается зелёным бейджем «Совпадает с эталоном» (§4.8).
- **Кнопка «⇄»** — переворот направления текущего задания на ходу: пользователь составил задание ru→en, захотел en→ru — переворачивает кнопкой, файл править не нужно. Кнопка скрыта (и клавиша `F` игнорируется с тостом), если направление зафиксировано: у колоды выключен реверс (`reverse: false` / `поворот: запрещен`, v1.11 — раньше задания можно было переворачивать вопреки шапке), полем `direction`, это задание из секции «Аудио», это **картинное задание** (картинка всегда вопросом) или колода грамматическая (`lang = base`).
- Самооценка: ✓ / ✗ (как во §5.2).

### 5.4 Горячие клавиши (ПК)

| Клавиша | Действие |
| --- | --- |
| Пробел / Enter | Переворот карточки или «Показать ответ» |
| 1 | ✓ — знал |
| 2 | ✗ — не знал |
| H | Подсказка |
| P | Повторить аудио текущей стороны |
| F | Перевернуть направление задания |
| Esc | Выйти из сессии |

Обработка через `e.code` (физическая клавиша) — хоткеи работают на любой раскладке, включая русскую.

### 5.5 Прогресс

- localStorage по ключу «колода + id карточки»: счётчики знал/не знал, дата последнего показа, использованные подсказки. Дата в схеме — задел под будущий SRS без миграции данных.
- Экспорт и импорт прогресса JSON-файлом — перенос между ПК и телефоном.
- Статистика по колоде: всего / знаю / ошибки; сброс прогресса кнопкой.

### 5.6 Синтез речи, громкость, выключение звука

- **Синтез речи** (`speechSynthesis`) — запаска для сторон без своего аудио (типовой случай — предложения): текст читает голос браузера. Язык определяется по алфавиту читаемого текста (v1.10): кириллица — русский голос; латиница — язык этой стороны из шапки (`lang`/`base`), если тот латинский (французский, немецкий…), иначе английский. Так колонки «наоборот» не заставляют синтез читать русский текст английским голосом. Голос подбирается по префиксу языка из списка голосов браузера; Chrome отдаёт список голосов асинхронно, поэтому сайт загружает и кеширует его при старте и ждёт `voiceschanged` (до 1,2 с) перед первым чтением — без этого браузер читает системным голосом по умолчанию (на русской машине всё звучит по-русски).
- **Переключатель 🗣** — на главной в «Настройках» и в шапке сессии (рядом с размером шрифта); состояние общее, хранится в localStorage. По умолчанию включён. Выключение останавливает текущее чтение. Файловое аудио всегда важнее синтеза.
- **Громкость** — слайдер (0–100 %, по умолчанию 70 %), там же на главной и в шапке сессии; применяется и к файлам, и к синтезу; хранится в localStorage. Перетаскивание слайдера снимает mute.
- **Mute 🔊/🔇** — полное выключение звука (файлы + синтез), там же; состояние хранится; включение mute останавливает текущее чтение, кнопка синтеза на карточке скрывается.
- Выход из сессии / уход со страницы сессии останавливает текущее чтение.

## 6. Интерфейс

- Сборка: **один самодостаточный файл `index.html`** (CSS и JS внутри, без шага сборки). Тренажёр и инструкция — два экрана одного приложения с hash-навигацией (`#/`, `#/instruction`, `#/session`); демо-колода вшита в файл и работает без интернета.
- Инструкция — отдельный экран с сайдбар-навигацией по разделам, якорными ссылками и копируемыми примерами (§7).
- **Главная, верхняя зона** (v1.12): две колонки (на телефоне — друг под другом). Слева панель «Настройки» строками (заголовки панелей — по центру): размер шрифта, размер картинок, синтез речи 🗣, громкость + mute, и строка «Прогресс» с иконками импорта 📥 / экспорта 📤 / сброса ✕ (подсказки — в title). Справа колонка: панель «Загрузить файлы с устройства» — три кнопки-иконки (📄 файлы, 📂 папка, 🗜 zip; названия — в подсказке при наведении) и строка вставки ссылки с «Добавить» (текстовые подсказки под кнопками убраны — всё описано в инструкции); под ней панель «Медиа». Ниже — «Мои колоды» (плитки «N карт · M заданий · ✓ K · ✗ X»), кнопка «Тренировать все колоды вместе», затем журнал на всю ширину.
- **Вшитая колода переименована в «Test»** (v1.11) — освобождает имя и служит живым примером формата, включая русский ключ шапки `поворот: разрешен`; у пользователей со старой версией название обновляется автоматически (id и прогресс сохраняются).
- Язык интерфейса: русский по умолчанию + переключатель на English, выбор сохраняется.
- Шрифт интерфейса — моноширинный (стек `ui-monospace → Cascadia Mono → SF Mono → Menlo → Consolas → DejaVu Sans Mono → monospace`), все размеры текста заданы в rem от базы `html{font-size:16px}`.
- **Размер шрифта** — селектор 85 / 100 / 115 / 130 / 150 %: в блоке «Настройки» на главной **и рядом с карточками в шапке сессии** (справа от названия колоды); выбор хранится в localStorage и применяется к базе rem при запуске, масштабируется весь интерфейс, включая кодбоксы инструкции.
- **Размер картинок** (v1.10) — селектор с четырьмя комфортными вариантами: **маленькие** (96 px), **средние** (160 px, по умолчанию), **крупные** (240 px), **очень крупные** (320 px) по высоте. Стоит в «Настройках» на главной рядом с размером шрифта и в шапке сессии; применяется ко всем картинкам карточек и заданий через CSS-переменную `--img-h` (пропорции сохраняются), выбор хранится в localStorage.
- **Звук** — в «Настройках» на главной и в шапке сессии: переключатель синтеза речи 🗣, слайдер громкости, кнопка mute 🔊/🔇 (§5.6). На узких экранах шапка сессии переносит название колоды на отдельную строку.
- **Плитка колоды**: счётчики и ✓/✗; подробности автосвязки («Аудио без пары», записи без файла, подсказки переименования) — в журнале (§4.6.1).
- Мобильная вёрстка: крупные кнопки под большой палец, тап по всей карточке, всё помещается без горизонтального скролла.
- **Медиа-библиотека (§3.1)** — панель «Медиа» на главной **под кнопками загрузки** (правая колонка; на телефоне — под панелью загрузки): состояние («Медиа предзагружено — N аудио · M картинок»), чипы подключённых источников (папки/архивы) и кнопка **«Очистить»** (отзывает blob-URL, обнуляет индекс и сбрасывает кеш «Аудио недоступно»). Повторная загрузка той же папки или архива обновляет содержимое этого источника целиком: переименованные и удалённые файлы убираются из библиотеки — «призраки» больше не ловятся автосвязкой и не попадают в «без пары» (v1.12). В панели «Загрузить файлы с устройства» — строка «Добавить» колоды по ссылке и три кнопки: «Выбрать файлы», «Выбрать папку», «Загрузить архив (.zip)».
- **Журнал** — панель на всю ширину под колодами; шрифт компактный; запись может нести строки-детали (подсказки переименования, записи без файла, «… ещё N»). Горячие клавиши на ПК (§5.4).

## 7. Страница инструкции — содержание

1. **Быстрый старт за 5 минут** — готовый шаблон колоды целиком, кнопка «Скопировать».
2. **Формат базы** — шапка (lang/base/reverse), разделы «Направление изучения и реверс» и «Задание с картинкой», секции `# Карточки` / `# Задания` / `# Аудио`, однострочные записи с вариантами через `;`, таблица модификаторов (`hint`, `audio`/`audio2`, `tags`, `id`, `reverse`, `direction`), правила разделения и экранирования.
3. **Картинки** — три способа + медиа-библиотека: папка/ZIP, сопоставление по имени, тихая пометка отсутствующих; **размер картинок** — четыре варианта в «Настройках» и в сессии.
4. **Аудио**:

   - **связка по имени без номера** — тексты до 6 слов;
   - **синтез речи, громкость, mute** — переключатели на главной и в сессии;
   - **как подключить аудио: папка или ZIP** (§3.1) — выкладывать mp3 в репозиторий не нужно; префикс папки в пути не важен; кириллица и в папке, и в ZIP (кодировка определяется сама, первые имена — в тосте);
   - **как создать свои аудио**:
     - **edge-tts** (рекомендуемый способ): бесплатно, нейроголоса Microsoft, десятки языков. Пример: `edge-tts --voice en-US-AriaNeural --text "Hello! How are you?" --write-media audio/hello-how-are-you.mp3`;

     - **Piper** — локальный оффлайн-синтез, быстрый, без интернета;
     - **Forvo** — живые записи носителей для отдельных слов;
     - платные сервисы максимального качества: Azure TTS, ElevenLabs, OpenAI TTS;
     - обычная запись голоса на телефоне;
     - при локальной работе имена могут быть любыми — латиница нужна только для выкладки в репозиторий;
   - заметка: позже в репозиторий добавим скрипт батч-генерации, который прочитает md-колоду и создаст mp3 для всех карточек сразу.
5. **Загрузка на сайт** — рекомендованные / ссылки (raw, кэш, «Обновить») / три кнопки устройства (файлы / папка / ZIP-архив), медиа-библиотека и её срок жизни, лимит памяти.
6. **Прогресс** — как считается, экспорт/импорт, сброс.
7. **Горячие клавиши** — таблица.
8. **FAQ и шаблоны** — типовые вопросы (включая «Аудио недоступно» и «какой ZIP подойдёт») и копируемые примеры колод.
